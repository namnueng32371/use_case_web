สูตรคะแนน: (ผลกระทบทางธุรกิจ × 0.35) + (ความเป็นไปได้ทางเทคนิค × 0.25) + (ความพร้อมของข้อมูล × 0.25) + ((6 − ความเสี่ยง) × 0.15) แล้วคูณ 20 เพื่อแปลงเป็นคะแนนเต็ม 100 — คะแนน ≥75 = ระดับสูง, 50–74 = ระดับกลาง, ต่ำกว่า 50 = ระดับต่ำ

ข้อมูลจะถูกบันทึกไว้ในฐานข้อมูลกลาง (MySQL) ผู้ใช้ทุกคนที่เข้าเครื่องมือนี้จะเห็นข้อมูลชุดเดียวกัน

ต้องใช้ AI (Claude) — ใช้ได้เฉพาะเมื่อเปิดผ่าน Claude Artifact · ถ้าเปิดไฟล์ HTML ในเครื่อง ส่วนนี้จะใช้งานไม่ได้

ให้ Claude วิเคราะห์ Spec และงบประมาณ Server AI ที่ควรใช้ โดยอิงจากรายละเอียด use case จริงในแท็บ "จัดลำดับ Use Case" — แบ่งวิเคราะห์ 3 กลุ่มตามระดับความสำคัญ: กลุ่มคะแนนสูง (สีเขียว, ≥75 คะแนน), กลุ่มคะแนนกลาง (สีน้ำตาล/ส้ม, 50-74 คะแนน) และ รวมทุก Use Case เมื่อเพิ่ม/ลบ/แก้ไข use case ระบบจะตรวจพบว่าผลวิเคราะห์เดิม "ล้าสมัย" แล้วให้กดวิเคราะห์ใหม่ได้ทันที ผลที่วิเคราะห์แล้วจะถูกบันทึกไว้ให้ทุกคนที่เปิดหน้านี้เห็นชุดเดียวกัน

1 USD ≈ บาท

Claude จะพิจารณาจากประเภทงาน AI (aiType), วิธีการเดิม, ข้อมูลที่มีอยู่, แนวทางหลังนำ AI มาใช้, จำนวนผู้ใช้, ความไวของข้อมูล, Latency/Availability ที่ต้องการของแต่ละ use case ในกลุ่มนั้นๆ แล้วเสนอสเปกฮาร์ดแวร์/สถาปัตยกรรมที่เหมาะสมและงบประมาณโดยประมาณ (ไม่ได้ยึดตาม Tier ที่ตายตัว) — ใช้เป็นข้อมูลประกอบการตัดสินใจของผู้บริหาร ไม่ใช่ใบเสนอราคาสุดท้าย

ภาพรวมทิศทางของ โครงการ AI Local GSK — สรุปจากไฟล์ “โครงการ AI Local GSK.xlsx” (ชีท โครงสร้างทีม, Flow การทำงาน, Design Server Local, Template User Case) รวมกับ use case จริงที่เก็บอยู่ในโปรแกรมนี้ หน้านี้ตอบคำถามเดียว: เก็บ use case เสร็จแล้วไปต่อทางไหน และอะไรต้องทำก่อน ตอนนี้เราอยู่ที่ เฟส 1 — เก็บ use case ซึ่งก็คือโปรแกรมนี้เอง

เส้นทางโครงการ 6 เฟส

1
เก็บ Use Case อยู่ที่นี่ กำลังทำ

Business Unit Champion ของแต่ละฝ่าย (AMD / GM / ผจก.ฝ่าย) ส่ง pain point เข้ามาผ่านโปรแกรมนี้ · แต่ละ use case ต้องกรอก ปัญหา / วิธีเดิม / ข้อมูลที่มี / ผลที่คาดหวัง แล้วให้คะแนน Impact · Feasibility · Data · Risk · เป้าหมายเฟสนี้คือได้รายการที่ประเมินความเป็นไปได้เบื้องต้นแล้ว ครบทุกบริษัทในเครือ

2
จัดลำดับ & อนุมัติ ถัดไปทันที

เรียงตามคะแนนในแท็บ “จัดลำดับ Use Case” · AI Lead ตั้งงบ คำนวณ ROI และเลือกว่าทำอะไรก่อน · ผ่าน Gate ธรรมาภิบาล ก่อนอนุมัติ — เช็ก PDPA (มีข้อมูลส่วนบุคคลไหม), Bias, ลิขสิทธิ์ข้อมูล · ปิดท้ายด้วยรายการ use case คลื่นแรกที่อนุมัติงบแล้ว

3
วางโครงสร้างพื้นฐาน & ตั้งทีม คู่ขนานกับเฟส 2

ซื้อ/ติดตั้ง Server Tier 1 (RTX 5090 32GB + vLLM) · ตั้งทีม AI Start ชุดเล็ก: AI Lead 1, AI Engineer/Builder 2, AI Ops/Trainer 1 · ดึงบทบาทเสริม (Product Owner, Research Analyst, Solution Designer, Governance) จาก Digital Development / QMR / HR แทนการจ้างใหม่

4
Build & Proof of Concept ต่อ use case

Research Analyst เช็กก่อนว่าข้อมูลพอไหม และควรใช้ RAG / Fine-tune / Prompt Engineering · ทำต้นแบบด้วยข้อมูลตัวอย่าง 10–20 รายการ · เอาผลไปคุยกับ AI Lead เพื่อตัดสิน GO / NO-GO ก่อนลงแรง build เต็มระบบ

5
Deploy & Adoption หลังผ่าน PoC

ปล่อยใช้งานจริง + เขียนคู่มือ + จัด workshop สั้น ๆ ให้แต่ละฝ่าย · AI Ops เฝ้า Model drift และ log รายวัน · Champion network เก็บ feedback ส่งกลับให้ AI Engineer ปรับ · ทำ post-launch review ที่ 30 / 60 / 90 วัน

6
ขยายผลระดับองค์กร ปีที่ 2–3 เป็นต้นไป

ขยับเป็น Server Tier 2 → Tier 3 เมื่อผู้ใช้พร้อมกันเกิน ~30 คน หรือต้องการ RAG ทั้งเครือ · ตั้งทีมเต็มรูปแบบ: Head of AI Unit, AI Strategy & Research, AI Engineering, MLOps Pipeline, AI Governance Committee, Data Governance · ทำ AI adoption ให้เป็นส่วนหนึ่งของ performance review

แผนงานรวมทั้งพอร์ต — จัดคลื่นตามคะแนน use case

แบ่ง use case ทั้งหมดเป็น 3 คลื่นตามคะแนนรวม (Impact 35% · Feasibility 25% · Data 25% · Risk 15%) แล้ววางเป็นไทม์ไลน์เดียว — คลื่นทำต่อกันตามลำดับ แต่ละคลื่นมีช่วงเตรียมการก่อน และทีมทำได้ทีละ 2 use case พร้อมกัน (งานถัดไปเข้าเมื่อมีเลนว่าง) ความยาวแท่ง = ระยะเวลาของแผนงาน use case นั้น (จากช่อง "ทรัพยากรและประมาณการ" ถ้าไม่ระบุ = 24 สัปดาห์) อัปเดตอัตโนมัติเมื่อแก้คะแนนหรือทรัพยากร

ชั้นแพลตฟอร์ม — ทำคู่ขนานทุกคลื่น

จากชีท Template User Case: บริการพื้นฐาน LLM API + AI Chatbot และ Embedding / RAG สำหรับ S.K.Polymer, Thairubbtech, Polymate (ฝ่ายขาย/ผลิต/ADMIN) เป็น “ชั้นแพลตฟอร์ม” ที่ทุก use case ด้านบนพึ่งพา — ต้องเริ่มตั้งแต่เฟส 3 · รายการที่ทำเครื่องหมาย “สูง — ต้องการด่วน” ในไฟล์คือ LLM API + Chatbot ของ S.K.Polymer ฝ่ายขาย (ภาษาไทย, ตอบเรียลไทม์ 0–2 วินาที) ให้จัดเป็นงานแรกของชั้นนี้ · เป้าหมายเปิดใช้ Q2–Q3 ปี 2570
