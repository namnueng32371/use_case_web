# คู่มือ AI Use Case Template v2

ไฟล์: `docs/AI_UseCase_Template_v2.xlsx`

## ภาพรวม: ข้อมูลไหลยังไง

```
sheet 1 (คนกรอก)  ──►  sheet 3 (คะแนน)   ──►  ตัดสินใจว่าทำอันไหนก่อน
     │
     └──ลิงก์ชื่อ──►  sheet 2 (คนกรอก)  ──►  กำหนด Spec Hardware + ราคา
```

**กฎที่ต้องเข้าใจก่อน:** sheet 2 ไม่มีผลกับคะแนนเลยแม้แต่ช่องเดียว
คะแนนมาจาก sheet 1 ล้วนๆ ส่วน sheet 2 ตอบคนละคำถามคือ "ถ้าจะทำ ต้องซื้อเครื่องแบบไหน"

สูตรคะแนน:

```
คะแนน = ( Impact×35% + Feasibility×25% + Data×25% + (6−Risk)×15% ) × 20
ระดับ:  สูง ≥ 75  |  กลาง 50–74  |  ต่ำ < 50
```

ช่วงคะแนนจริงคือ **20–100** ไม่ใช่ 0–100 — กรอกแย่ที่สุดทุกช่องยังได้ 20
(`(1×0.35 + 1×0.25 + 1×0.25 + 1×0.15) × 20 = 20`)

`6 − Risk` คือการกลับด้าน เพราะความเสี่ยงสูง = คะแนนควรต่ำ
ส่วน `× 20` คือการขยายสเกลจาก 1–5 ให้เป็น 20–100 ที่คนอ่านเข้าใจง่ายกว่า

## Sheet 1 : `1-UseCase ทั้งหมด` (23 คอลัมน์)

### กลุ่มที่เข้าสูตรคะแนนโดยตรง — 10 ช่อง

| คอลัมน์ | ชื่อ | เป็นคะแนนอะไร | วิธีแปลง |
|---|---|---|---|
| **I** | เวลาที่ใช้กับงานนี้ตอนนี้ (ยังไม่ใช้ AI) | Impact | dropdown 5 ช่วง: <4 ชม.=1 · 4–10=2 · 10–20=3 · 20–40=4 · >40=5 |
| **J** | มูลค่าความเสียหาย/ปี | Impact | dropdown 5 ช่วง: ประเมินไม่ได้=ไม่คิด · <1แสน=2 · 1–5แสน=3 · 5แสน–2ล้าน=4 · >2ล้าน=5 |
| **L** | รูปแบบข้อมูล | Data | ฐานข้อมูล=5 · Excel=4 · รูป=3 · เสียง=2 · กระดาษ=1 |
| **M** | ข้อมูลย้อนหลัง | Data | >3ปี=5 · 1–3ปี=4 · <1ปี=2 · ยังไม่มี=1 |
| **O** | สิทธิ์นำข้อมูลมาใช้ | Data | อยู่ในมือแผนกเราเอง=5 · ต้องขออนุมัติจากแผนกอื่น/IT=3 · เป็นของลูกค้า/vendor หรือยังไม่แน่ใจ=1 |
| **P** | ระบบเดิมที่ต้องเชื่อม | Feasibility | ไม่มี=5 · ส่งไฟล์ได้=3 · ยังไม่แน่ใจ=2 · เชื่อมตรงระบบหลัก=1 |
| **Q** | มีคนดูแลต่อมั้ย | Feasibility | มี=5 · ยังไม่แน่ใจ=3 · ไม่มี=1 |
| **R** | ผลกระทบถ้า AI ผิด | Risk | สูง=5 · กลาง=3 · ต่ำ=1 |
| **S** | ต้องตรวจซ้ำมั้ย | Risk | ทุกครั้ง=4 · สุ่ม=2 · ไม่ต้อง=1 |
| **T** | ระดับความลับข้อมูล | Risk **+ Hardware** | ลับมาก=5 · ลับ=4 · ภายใน=2 · สาธารณะ=1 |

> **T เป็นช่องเดียวที่ถูกใช้ 2 ที่** — ทั้งคำนวณ Risk และตัดสินว่าระบบต้องอยู่
> On-premise หรือใช้ Cloud ได้

**O ไม่ใช่ "มีข้อมูลมั้ย" แต่คือ "เอามาใช้ได้จริงมั้ย"** — เจอบ่อยว่ามีข้อมูลครบแต่ใช้ไม่ได้
เพราะเป็นของลูกค้าที่มี NDA หรืออยู่ในเครื่องจักรที่ vendor ล็อกไว้ ถ้าไม่ถามช่องนี้
คะแนน Data จะออกมาสูงลิ่วแล้วไปตายตอนเริ่มโปรเจกต์จริง

### ช่องบังคับ 10 ช่อง

**I, J, L, M, O, P, Q, R, S, T** (= 10 ช่องที่คิดคะแนนพอดี) ต้องกรอกครบ ระบบถึงจะคำนวณให้
ถ้าขาดแม้ช่องเดียว sheet 3 จะขึ้น **"ข้อมูลไม่ครบ"** แทนคะแนน และไม่เข้าการจัดอันดับ

ถ้าตีมูลค่าความเสียหายเป็นเงินไม่ได้ ให้เลือก **"ประเมินเป็นเงินไม่ได้"**
ระบบจะใช้เฉพาะชั่วโมงคิด Impact — **ไม่ได้หักคะแนน** (ในตารางจะขึ้นเป็น `-`)

### กลุ่มที่ไม่เข้าสูตร แต่ AI อ่านตอนวิเคราะห์ — 4 ช่อง

| คอลัมน์ | ชื่อ | ทำไมต้องมี |
|---|---|---|
| **F** | ปัญหาที่ต้องการแก้ | AI ใช้ทบทวนว่าคะแนนสมเหตุสมผลมั้ย และแนะนำประเภท AI ที่เหมาะ |
| **G** | วิธีการทำงานปัจจุบัน (*Existing Work*) | AI ใช้เข้าใจกระบวนการเดิม เพื่อออกแบบ Flow ใหม่ |
| **H** | แนวทางหลังนำ AI มาใช้ (*Description for Redesign*) | บอกว่าอยากให้ AI ทำอะไร — ใช้เลือกสถาปัตยกรรมและโมเดล |
| **K** | ข้อมูลที่มีอยู่ตอนนี้ (*Data Available*) | AI ตรวจว่า dropdown ที่เลือกตรงกับความจริงมั้ย |
| **N** | ปริมาณข้อมูลโดยประมาณ | มีตัวอย่างพอเทรนมั้ย (4,000 รูป พอ / 50 รูป ไม่พอ) |

G, H, K คือ 3 คอลัมน์ที่ยกมาตรงจาก Excel template เดิมของ E&E/Prod

### กลุ่มอ้างอิง ไม่คำนวณ — 8 ช่อง

A (No.) · B (ชื่อ) · C (บริษัท) · D (แผนก) · E (Owner) · W (หมายเหตุ)

**U (ความสำคัญที่แผนกอยากได้)** และ **V (ต้องการใช้ภายใน)** — จงใจไม่เอาเข้าสูตร เพราะ
ทุกแผนกจะเลือก "สูง - ต้องการด่วน" หมด ถ้าเอามาคิดก็ไม่ช่วยแยกอะไร
แต่มีประโยชน์ตรงที่เอาไป**เทียบกับคะแนนจริง** — ถ้าแผนกบอกด่วนมากแต่คะแนนออกมา 35
แปลว่าต้องคุยกันว่าทำไมต่างกัน

## Sheet 2 : `2-รายละเอียดเทคนิค` (19 คอลัมน์)

A, B, C ลิงก์อัตโนมัติจาก sheet 1 — ที่เหลือทั้งหมดใช้กำหนด Hardware
ตอบคำถาม 3 ข้อ:

### คำถามที่ 1: ต้องใช้ GPU มั้ย (ตัวคูณราคาที่ใหญ่ที่สุด)

| คอลัมน์ | ชื่อ | บอกอะไร |
|---|---|---|
| **D** | ประเภทข้อมูล Input | รูป/วิดีโอ = GPU แน่นอน · ตัวเลข/ตาราง = CPU พอ |
| **M** | Latency ที่รับได้ | Real-time = GPU · Batch = CPU พอ แม้เป็นงานภาพ |
| **P** | ความต้องการโมเดล | Fine-tune = ต้องมี GPU ตอนเทรนด้วย ไม่ใช่แค่ตอนใช้ |

> **D × M คือคู่ที่ตัดสินใจ** — *รูปภาพ + Real-time* = ต้อง GPU
> แต่ *รูปภาพ + Batch* = รันกลางคืนด้วย CPU ได้ ประหยัดหลายแสน

### คำถามที่ 2: ต้องใหญ่แค่ไหน

| คอลัมน์ | ชื่อ | บอกอะไร |
|---|---|---|
| **F** | **Peak concurrent** | **สำคัญที่สุดในกลุ่มนี้** — ตัดสินจำนวน GPU/เครื่อง (100 คน/วันกระจายทั้งวัน ≠ 100 คนพร้อมกันตอน 9 โมง) |
| **E** | Users/วัน | ประมาณ load รวม |
| **G** | Requests/วัน | คำนวณ throughput |
| **J** | จำนวนรูป/วัน | งานภาพ: GPU ตัวเดียวพอมั้ย |

E, F, G, H, I, J เป็น dropdown แบบช่วง ไม่ใช่ช่องพิมพ์ตัวเลข — เพราะการตั้ง spec
ดูที่ **ลำดับขนาด** ไม่ใช่ตัวเลขเป๊ะ (10 กับ 12 users ไม่ต่างกัน แต่ 10 กับ 1,000 ต่างกันมาก)
| **K** | ความละเอียดรูป | ตัดสินขนาด VRAM |
| **L** | ภาษาที่ต้องการ | ไทยต้องใช้โมเดลใหญ่กว่า → RAM/VRAM มากกว่า |
| **N** | Availability | 24×7 = ต้องมีเครื่องสำรอง (ราคา ×2) |

### คำถามที่ 3: เก็บเท่าไหร่ / ตั้งที่ไหน

| คอลัมน์ | ชื่อ | บอกอะไร |
|---|---|---|
| **H** | ขนาด Input/วัน (GB) | Storage ที่โตขึ้นเรื่อยๆ |
| **I** | ขนาดคลังเอกสารทั้งหมด (GB) | งาน RAG: ขนาด RAM + Vector DB (คนละตัวกับ H) |
| **O** | ต้องติดตั้งที่ไหน | **On-prem vs Cloud — ต่างกันหลักแสนถึงหลักล้าน** |
| **Q** | งบประมาณที่ตั้งไว้ | กรอบที่ต้องออกแบบให้อยู่ใน |
| **R** | ข้อจำกัดอื่นๆ | เช่น "พื้นที่ติดกล้องจำกัด" |

S = ผู้ให้ข้อมูลเทคนิค (อ้างอิงเฉยๆ)

## Sheet 3 : `3-คะแนนและลำดับ` (21 คอลัมน์)

ไม่ต้องกรอกอะไร ทุกช่องเป็นสูตร อ่านจาก sheet 1 อย่างเดียว

| คอลัมน์ | แสดงอะไร |
|---|---|
| A–C | No. / ชื่อ / แผนก (ลิงก์) |
| D–F | ชม.→คะแนน · มูลค่า→คะแนน · **Impact** |
| G–J | รูปแบบ · ย้อนหลัง · สิทธิ์ · **Data** |
| K–M | ระบบเดิม · คนดูแล · **Feasibility** |
| N–Q | AI ผิด · ตรวจซ้ำ · ความลับ · **Risk** |
| R–T | **คะแนนรวม · ระดับ · อันดับ** |
| U | **ช่องบังคับที่ยังไม่ได้กรอก** (0 = ครบ) |

### เมื่อกรอกไม่ครบ

| กรณี | คะแนนรวม | ระดับ | อันดับ | ช่องที่ขาด |
|---|---|---|---|---|
| ครบ | 89.0 | สูง | 1 | 0 |
| ขาด 2 ช่อง | *(ว่าง)* | **ข้อมูลไม่ครบ** | *(ว่าง)* | **2** |
| ยังไม่ได้กรอก Use Case | *(ว่าง)* | *(ว่าง)* | *(ว่าง)* | *(ว่าง)* |

ช่อง "ระดับ" และ "ช่องที่ขาด" ขึ้นพื้นแดงอัตโนมัติ · คะแนนย่อยที่กรอกไปแล้วยังแสดงปกติ ·
กรอกครบเมื่อไหร่คะแนนขึ้นเอง ไม่ต้องกดอะไร

แสดงคะแนนย่อยทุกตัว เพราะเวลาผู้บริหารถาม *"ทำไมอันนี้ได้ 45"*
จะชี้ได้ทันทีว่า "เพราะข้อมูลยังเป็นกระดาษ (Data=1) และขอใช้ข้อมูลไม่ได้"

คะแนนรวมไล่สีอัตโนมัติ: เขียว ≥75 · เหลือง 50–74 · เทา <50
แถวที่ 6 เป็น Use Case ตัวอย่าง (Auto Inspection = 89.0) ไม่นับเข้าการจัดอันดับ
