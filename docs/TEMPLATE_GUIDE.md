# คู่มือ AI Use Case Template v2

ไฟล์: `docs/AI_UseCase_Template_v2.xlsx`

## ภาพรวม: ข้อมูลไหลยังไง

```
sheet 1 (คนกรอก)  ──►  sheet 3 (คะแนน)   ──►  ตัดสินใจว่าทำอันไหนก่อน
     │
     └──ลิงก์ชื่อ──►  sheet 2 (คนกรอก)  ──►  กำหนด Spec Hardware + ราคา
```

**กฎที่ต้องเข้าใจก่อน:** sheet 2 ไม่มีผลกับคะแนนเลยแม้แต่ช่องเดียว
คะแนนมาจาก sheet 1 ล้วนๆ ส่วน sheet 2 ตอบคนละคำถามคือ "ถ้าจะทำ ต้องซื้อเครื่องแบบไหน"

สูตรคะแนน:

```
คะแนน = ( Impact×35% + Feasibility×25% + Data×25% + (6−Risk)×15% ) × 20
ระดับ:  สูง ≥ 75  |  กลาง 50–74  |  ต่ำ < 50
```

ช่วงคะแนนจริงคือ **20–100** ไม่ใช่ 0–100 — กรอกแย่ที่สุดทุกช่องยังได้ 20
(`(1×0.35 + 1×0.25 + 1×0.25 + 1×0.15) × 20 = 20`)

`6 − Risk` คือการกลับด้าน เพราะความเสี่ยงสูง = คะแนนควรต่ำ
ส่วน `× 20` คือการขยายสเกลจาก 1–5 ให้เป็น 20–100 ที่คนอ่านเข้าใจง่ายกว่า

### คอลัมน์ P — ความหมายของแต่ละระดับ

ถามว่า **AI ที่จะสร้างต้องไปยุ่งกับระบบไอทีเดิมมากแค่ไหน** ไม่ได้วัดที่ความยากทางเทคนิค
อย่างเดียว แต่วัดที่ **ต้องพึ่งคนอื่น (IT / vendor) แค่ไหน** — ซึ่งเป็นสาเหตุที่โปรเจกต์ AI
ในโรงงานส่วนใหญ่ล่ม ไม่ใช่เพราะ AI ไม่แม่น แต่เพราะรอเชื่อมระบบไม่ได้สักที

| ตัวเลือก | ตัวอย่าง |
|---|---|
| ไม่ต้องยุ่งกับระบบไหน | ติดกล้องใหม่ที่สายพาน AI โชว์ผลบนจอของมันเอง |
| แค่ export ไฟล์ก็พอ | ดึงรายงานจาก ERP เป็น Excel ทุกเช้า → AI วิเคราะห์ → ส่งผลเป็นไฟล์ |
| ต้องอ่าน/เขียนในระบบโดยตรง | AI ตรวจเสร็จต้องเขียนผลเข้า MES ทันทีเพื่อสั่งหยุดสายพาน |

**วิธีเลือก:** ถามว่า *"ถ้า export เป็น Excel มาให้ AI ทุกเช้า แล้วเอาผลไปพิมพ์ใส่ระบบเองทีหลัง
งานนี้ยังใช้ได้มั้ย"* — ถ้าใช้ได้ = เลือกตัวกลาง ถ้าต้องทันทีอัตโนมัติเท่านั้น = เลือกตัวล่าง

> **T เป็นช่องเดียวที่ถูกใช้ 2 ที่** — ทั้งคำนวณ Risk และกำหนดว่าต้องเข้ารหัส
> จำกัดสิทธิ์ และเก็บ log การเข้าถึงระดับไหน

### ข้อกำหนดของโครงการ : Server ตั้งในบริษัทที่เดียว ไม่ใช้ Cloud ทุกกรณี

คำถามเรื่องที่ตั้งจึงไม่ใช่ "ในหรือนอกบริษัท" แต่เป็น **"รวมศูนย์ที่ server กลาง
หรือต้องมีเครื่องแยกที่หน้างาน"** — งาน Real-time ที่ตรวจชิ้นงานบนสายพานมักต้องมี
เครื่องติดข้างเครื่องจักร ไม่ใช่ส่งรูปวิ่งข้ามเครือข่ายไป server กลางแล้วรอผลกลับ

ผลที่ตามมาคือวิธีคิดราคาเปลี่ยนไปด้วย — ไม่ใช่ "บวกราคาเครื่องของแต่ละ use case"
แต่เป็น **"เครื่องเดียวที่จะซื้อ ต้องแรงแค่ไหนถึงรองรับงานที่จะทำจริงและขยายต่อได้"**
งานข้อความหลายอันโหลดโมเดลตัวเดียวแล้วเรียกใช้ร่วมกันได้ ประหยัดกว่าซื้อแยกมาก

**O ไม่ใช่ "มีข้อมูลมั้ย" แต่คือ "เอามาใช้ได้จริงมั้ย"** — เจอบ่อยว่ามีข้อมูลครบแต่ใช้ไม่ได้
เพราะเป็นของลูกค้าที่มี NDA หรืออยู่ในเครื่องจักรที่ vendor ล็อกไว้ ถ้าไม่ถามช่องนี้
คะแนน Data จะออกมาสูงลิ่วแล้วไปตายตอนเริ่มโปรเจกต์จริง

### ช่องบังคับ 10 ช่อง

**I, J, L, M, O, P, Q, R, S, T** (= 10 ช่องที่คิดคะแนนพอดี) ต้องกรอกครบ ระบบถึงจะคำนวณให้
ถ้าขาดแม้ช่องเดียว sheet 3 จะขึ้น **"ข้อมูลไม่ครบ"** แทนคะแนน และไม่เข้าการจัดอันดับ

ถ้าตีมูลค่าความเสียหายเป็นเงินไม่ได้ ให้เลือก **"ประเมินเป็นเงินไม่ได้"**
ระบบจะใช้เฉพาะชั่วโมงคิด Impact — **ไม่ได้หักคะแนน** (ในตารางจะขึ้นเป็น `-`)

### กลุ่มที่ไม่เข้าสูตร แต่ AI อ่านตอนวิเคราะห์ — 5 ช่อง

| คอลัมน์ | ชื่อ | ทำไมต้องมี |
|---|---|---|
| **F** | ปัญหาที่ต้องการแก้ | AI ใช้ทบทวนว่าคะแนนสมเหตุสมผลมั้ย และแนะนำประเภท AI ที่เหมาะ |
| **G** | วิธีการทำงานปัจจุบัน (*Existing Work*) | AI ใช้เข้าใจกระบวนการเดิม เพื่อออกแบบ Flow ใหม่ |

**คอลัมน์ N ยังไม่ถูกนำไปคิดคะแนน** เป็นข้อความอิสระให้ AI อ่านอย่างเดียว
หน่วยที่ใช้นับต่างกันตามประเภทงาน จึงมีกล่องคำอธิบายเด้งขึ้นตอนคลิกช่อง:

| วิเคราะห์การผลิต | กี่ล็อต กี่แถวข้อมูล |
| จัดคน / แนะนำ | เคยจัดจริงมากี่ครั้ง |

นับเฉพาะข้อมูลที่**รู้คำตอบแล้ว** (เช่น รูปที่มาร์คแล้วว่าดี/เสีย) —

ช่อง F, G, H, K, N ทั้ง 5 ช่องมีกล่องคำอธิบายแบบนี้ เพราะเป็นช่องพิมพ์อิสระที่

### โซน A — แผนกกรอก (D–P)

| คอลัมน์ | ถามอะไร | เอาไปทำอะไร |
|---|---|---|
| **D** | ข้อมูลที่ AI ต้องอ่าน/ดู เป็นแบบไหน | รูป/วิดีโอ = GPU แน่นอน · ตัวเลข/ตาราง = CPU พอ |
| **E** | จำนวนคนที่ใช้งาน/วัน | ประมาณ load รวม |
| **F** | ช่วงพีค มีคนใช้พร้อมกันมากสุดกี่คน | **ตัดสินจำนวน GPU** (100 คน/วันกระจายทั้งวัน ≠ 100 คนพร้อมกันตอน 9 โมง) |

> **E กับ F ใช้สเกลต่างกันโดยตั้งใจ** — E นับคนทั้งหมดตลอดวัน (เริ่มที่ 1–10 คน)
> ส่วน F นับคนที่กดพร้อมกัน (เริ่มที่ 1–2 คน) เพราะ F จะน้อยกว่า E เสมอ
> ทั้งสองช่องมีกล่องคำอธิบายเด้งขึ้นตอนคลิก และ **ถ้าตัวเลขดูขัดกัน
> ช่อง F จะขึ้นพื้นสีส้มเตือนอัตโนมัติ**

เกณฑ์เตือน: ขอบล่างของช่วงพีค เกินครึ่งหนึ่งของจำนวนคนต่อวันสูงสุด
(ไม่ได้แปลว่าผิด แต่ควรกลับไปทบทวน) — คู่ที่จะขึ้นสีส้ม:

| คนใช้/วัน | ช่วงพีคที่จะถูกเตือน |
|---|---|
| 1 – 10 | 6–20 · 21–50 · มากกว่า 50 |
| 11 – 50 | มากกว่า 50 |
| 51 คนขึ้นไป | ไม่เตือน (สัดส่วนสมเหตุสมผลได้ทุกแบบ) |
| **G** | ใช้งานกี่ครั้ง/วัน | คำนวณ throughput |
| **H** | จำนวนกล้อง/จุดตรวจที่ทำงานพร้อมกัน | งาน Real-time สเปกขึ้นกับจำนวนสายที่ประมวลผลขนานกัน ไม่ใช่ยอดรูปต่อวัน |
| **I** | ภาษาที่ต้องการ | ไทยต้องใช้โมเดลใหญ่กว่า → VRAM มากกว่า |
| **J** | รอผลได้นานแค่ไหน | **Real-time = GPU · Batch = CPU พอ แม้เป็นงานภาพ** |
| **K** | ต้องใช้งานช่วงเวลาไหน | 24×7 = ต้องมีเครื่องสำรอง |
| **L** | ถ้าช่วงไหนคนใช้เยอะ แล้วงานนี้ช้าลง จะเป็นปัญหามั้ย | **แปลเป็น "ต้องมี GPU ของตัวเองมั้ย"** |
| **M** | ต้องเก็บข้อมูลย้อนหลังกี่ปี | คูณกับขนาด Input/วัน = storage ที่ต้องซื้อ |
| **N–P** | งบประมาณ · ข้อจำกัด · ผู้ให้ข้อมูล | อ้างอิง |

**คอลัมน์ L สำคัญที่สุดในโซนนี้** — เดิมเขียนว่า "แชร์เครื่องกับ use case อื่นได้มั้ย"
ซึ่งหัวหน้าแผนกตอบไม่ได้ (ไม่รู้ว่า "เครื่อง" คืออะไร ไม่รู้ว่ามี use case อื่นอะไรบ้าง)
ถ้าถามแบบนั้นทุกคนจะเลือก "ต้องมีเครื่องของตัวเอง" ไว้ก่อนเพื่อความปลอดภัย → **งบบานปลาย**

เขียนใหม่ให้ถามผลกระทบต่องานของเขาเอง ซึ่งตอบได้แน่นอน แล้วทีมส่วนกลางแปลเป็น
ข้อกำหนดทางเทคนิคเอง

| **T** | ติดตั้งแบบไหน (server กลาง / เครื่องที่หน้างาน) | เรื่องสถาปัตยกรรม |
| **U** | ต้องสอนโมเดลด้วยข้อมูลบริษัทมั้ย | ศัพท์เทคนิค (สำเร็จรูป / RAG / Fine-tune) |
| **V** | ต้องเทรนโมเดลใหม่บ่อยแค่ไหน | ต้องรู้ก่อนว่าโมเดลทำงานยังไง |

**คอลัมน์ U มี 3 ระดับ ไม่ใช่ 2** — ตัวกลาง "ไม่ต้องเทรน แต่ให้อ่านเอกสารบริษัท (RAG)"
สำคัญมาก เพราะ use case งานเอกสาร/chatbot ส่วนใหญ่ตกอยู่ตรงนี้ ถ้าไม่มีตัวเลือกนี้
คนจะเลือก "ต้อง Fine-tune" ทั้งที่ไม่ต้อง → ระบบคิดว่าต้องซื้อ GPU สำหรับเทรนเพิ่มโดยไม่จำเป็น

**คอลัมน์ V มีตัวเลือก "ไม่ต้องเทรนเลย"** ซึ่งต่างจาก "ครั้งเดียวจบ"
(ครั้งเดียวจบ = ยังต้องเทรน 1 ครั้ง จึงยังต้องหา GPU มาเทรน)
