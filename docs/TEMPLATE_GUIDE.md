ไฟล์: `docs/AI_UseCase_Template_v2.xlsx` (สร้างจาก `docs/build_template.py`)

มี 5 sheet: `คู่มือการใช้งาน` · `1-UseCase ทั้งหมด` · `2-รายละเอียดเทคนิค` · `3-คะแนนและลำดับ` · `DATA`

> ไฟล์ .xlsx สร้างใหม่แล้ว (2026-10-12) มีคอลัมน์ **AA (สถานที่ตั้งที่ใช้งาน)** ครบ 27 คอลัมน์ ยังไม่ได้เปิดตรวจด้วย Excel จริง
>
> ไฟล์ที่ commit ตอนนี้มี **use case จริง 3 รายการในแถว 7–9 ของ sheet 1** (จาก `AI Transformation Plan (Prod) E&E.xlsx` เฉพาะแถวที่มี Redesign) สร้างด้วยตัวเลือก `SEED_JSON=<ไฟล์ JSON> python docs/build_template.py` — ใส่เฉพาะช่องข้อความที่มีในต้นฉบับ (บริษัท หน่วยงาน QWP kQI ขั้นตอน ปัญหา Existing Work Redesign Data Available หมายเหตุ) ช่อง dropdown ทั้งหมดเว้นว่าง รันสคริปต์โดยไม่กำหนด `SEED_JSON` จะได้ template ว่าง

## ภาพรวม: ข้อมูลไหลยังไง

```
sheet 1 (คนกรอก)  ──►  sheet 3 (คะแนน)   ──►  ตัดสินใจว่าทำอันไหนก่อน
     │
     └──ลิงก์ชื่อ──►  sheet 2 (คนกรอก)  ──►  กำหนด Spec Hardware + ราคา
```

**กฎที่ต้องเข้าใจก่อน:** sheet 2 ไม่มีผลกับคะแนนเลยแม้แต่ช่องเดียว
คะแนนมาจาก sheet 1 ล้วนๆ ส่วน sheet 2 ตอบคนละคำถามคือ "ถ้าจะทำ ต้องซื้อเครื่องแบบไหน"

สูตรคะแนน:

```
คะแนน = ( Impact×35% + Feasibility×25% + Data×25% + (6−Risk)×15% ) × 20
ระดับ:  สูง ≥ 75  |  กลาง 50–74  |  ต่ำ < 50
```

ช่วงคะแนนจริงคือ **20–100** ไม่ใช่ 0–100 — กรอกแย่ที่สุดทุกช่องยังได้ 20
(`(1×0.35 + 1×0.25 + 1×0.25 + 1×0.15) × 20 = 20`)

`6 − Risk` คือการกลับด้าน เพราะความเสี่ยงสูง = คะแนนควรต่ำ
ส่วน `× 20` คือการขยายสเกลจาก 1–5 ให้เป็น 20–100 ที่คนอ่านเข้าใจง่ายกว่า

| **W** | ข้อมูลชุดนี้ลับแค่ไหน | Risk **+ Hardware** | ลับมาก (PDPA)=5 · ลับ=4 · ภายใน=2 · สาธารณะ=1 |

### คอลัมน์ S — ความหมายของแต่ละระดับ

ถามว่า **AI ที่จะสร้างต้องไปยุ่งกับระบบไอทีเดิมมากแค่ไหน** ไม่ได้วัดที่ความยากทางเทคนิค
อย่างเดียว แต่วัดที่ **ต้องพึ่งคนอื่น (IT / vendor) แค่ไหน** — ซึ่งเป็นสาเหตุที่โปรเจกต์ AI
ในโรงงานส่วนใหญ่ล่ม ไม่ใช่เพราะ AI ไม่แม่น แต่เพราะรอเชื่อมระบบไม่ได้สักที

| ตัวเลือก | ตัวอย่าง |
|---|---|
| ไม่ต้องยุ่งกับระบบไหน | ติดกล้องใหม่ที่สายพาน AI โชว์ผลบนจอของมันเอง |
| แค่ export ไฟล์ก็พอ | ดึงรายงานจาก ERP เป็น Excel ทุกเช้า → AI วิเคราะห์ → ส่งผลเป็นไฟล์ |
| ต้องอ่าน/เขียนในระบบโดยตรง | AI ตรวจเสร็จต้องเขียนผลเข้า MES ทันทีเพื่อสั่งหยุดสายพาน |

**วิธีเลือก:** ถามว่า *"ถ้า export เป็น Excel มาให้ AI ทุกเช้า แล้วเอาผลไปพิมพ์ใส่ระบบเองทีหลัง
งานนี้ยังใช้ได้มั้ย"* — ถ้าใช้ได้ = เลือกตัวกลาง ถ้าต้องทันทีอัตโนมัติเท่านั้น = เลือกตัวล่าง

> **W เป็นช่องเดียวที่ถูกใช้ 2 ที่** — ทั้งคำนวณ Risk และกำหนดว่าต้องเข้ารหัส
> จำกัดสิทธิ์ และเก็บ log การเข้าถึงระดับไหน

### ข้อกำหนดของโครงการ : On-premise ทุกงาน ไม่ใช้ Cloud · ทุกสถานที่ตั้งมี Server ของตัวเอง

ไม่มีงานไหนออกนอกบริษัท และแต่ละโรงงาน/สาขา (คอลัมน์ **AA**) มี Server ของตัวเอง
ภายในที่ตั้งเดียวกันยังมีคำถามว่า **"รันที่ server ของที่ตั้ง หรือต้องมีเครื่องแยกที่หน้างาน"**
— งาน Real-time ที่ตรวจชิ้นงานบนสายพานมักต้องมีเครื่องติดข้างเครื่องจักร
ไม่ใช่ส่งรูปวิ่งข้ามเครือข่ายไป server แล้วรอผลกลับ

ผลที่ตามมาคือวิธีคิดราคาเปลี่ยนไปด้วย — ไม่ใช่ "บวกราคาเครื่องของแต่ละ use case"
แต่เป็น **"เครื่องของแต่ละที่ตั้ง ต้องแรงแค่ไหนถึงรองรับงานที่จะทำจริงและขยายต่อได้"**
แล้วรวมงบทุกที่ตั้ง งานข้อความหลายอันในที่ตั้งเดียวกันโหลดโมเดลตัวเดียวแล้วเรียกใช้ร่วมกันได้
ประหยัดกว่าซื้อแยกมาก

**R ไม่ใช่ "มีข้อมูลมั้ย" แต่คือ "เอามาใช้ได้จริงมั้ย"** — เจอบ่อยว่ามีข้อมูลครบแต่ใช้ไม่ได้
เพราะเป็นของลูกค้าที่มี NDA หรืออยู่ในเครื่องจักรที่ vendor ล็อกไว้ ถ้าไม่ถามช่องนี้
คะแนน Data จะออกมาสูงลิ่วแล้วไปตายตอนเริ่มโปรเจกต์จริง

### ช่องบังคับ 10 ช่อง

**L, M, O, P, R, S, T, U, V, W** (= 10 ช่องที่คิดคะแนนพอดี) ต้องกรอกครบ ระบบถึงจะคำนวณให้
ถ้าขาดแม้ช่องเดียว sheet 3 จะขึ้น **"ข้อมูลไม่ครบ"** แทนคะแนน และไม่เข้าการจัดอันดับ

ถ้าตีมูลค่าความเสียหายเป็นเงินไม่ได้ ให้เลือก **"ประเมินเป็นเงินไม่ได้"**
ระบบจะใช้เฉพาะชั่วโมงคิด Impact — **ไม่ได้หักคะแนน** (ในตารางจะขึ้นเป็น `-`)

### กลุ่มที่ไม่เข้าสูตร แต่ AI อ่านตอนวิเคราะห์ — 5 ช่อง

| คอลัมน์ | ชื่อ | ทำไมต้องมี |
|---|---|---|
| **I** | ปัญหาที่ต้องการแก้ | AI ใช้ทบทวนว่าคะแนนสมเหตุสมผลมั้ย และแนะนำประเภท AI ที่เหมาะ |
| **J** | วิธีการทำงานปัจจุบัน (*Existing Work*) | AI ใช้เข้าใจกระบวนการเดิม เพื่อออกแบบ Flow ใหม่ |
| **K** | แนวทางหลังนำ AI มาใช้ (*Description for Redesign*) | บอกว่าอยากให้ AI ทำอะไร — ใช้เลือกสถาปัตยกรรมและโมเดล |
| **N** | ข้อมูลที่มีอยู่ตอนนี้ (*Data Available*) | AI ตรวจว่า dropdown ที่เลือกตรงกับความจริงมั้ย |
| **Q** | ปริมาณข้อมูลโดยประมาณ | มีตัวอย่างพอเทรนมั้ย (4,000 รูป พอ / 50 รูป ไม่พอ) |

**คอลัมน์ Q ยังไม่ถูกนำไปคิดคะแนน** เป็นข้อความอิสระให้ AI อ่านอย่างเดียว
หน่วยที่ใช้นับต่างกันตามประเภทงาน จึงมีกล่องคำอธิบายเด้งขึ้นตอนคลิกช่อง:

| ประเภทงาน | นับเป็น |
|---|---|
| ตรวจภาพ | กี่รูป |
| หาสาเหตุปัญหา / NC | กี่เคส กี่ใบ |
| ค้นหา–สรุปเอกสาร | กี่ไฟล์ กี่ฉบับ |
| ทำนายเครื่องเสีย | เคยเสียมากี่ครั้ง |
| วิเคราะห์การผลิต | กี่ล็อต กี่แถวข้อมูล |
| จัดคน / แนะนำ | เคยจัดจริงมากี่ครั้ง |

นับเฉพาะข้อมูลที่**รู้คำตอบแล้ว** (เช่น รูปที่มาร์คแล้วว่าดี/เสีย) —
ข้อมูลดิบที่ยังไม่ได้แยกใช้เทรนไม่ได้

ช่อง I, J, K, N, Q ทั้ง 5 ช่องมีกล่องคำอธิบายแบบนี้ เพราะเป็นช่องพิมพ์อิสระที่
คนกรอกมักไม่แน่ใจว่าต้องเขียนละเอียดแค่ไหน

J, K, N คือ 3 คอลัมน์ที่ยกมาตรงจาก Excel template เดิมของ E&E/Prod

### กลุ่มอ้างอิงระบบคุณภาพ — 3 ช่อง

| คอลัมน์ | ชื่อ | ใช้ทำอะไร |
|---|---|---|
| **F** | QWP อ้างอิง (รหัส / ชื่อเอกสาร) | โยง use case กลับไปหาเอกสารคุณภาพต้นทาง |
| **G** | kQI / QI ที่เกี่ยวข้อง | บอกว่า use case นี้ไปขยับตัวชี้วัดตัวไหน |

ไม่ได้เอาไปคิดคะแนน แต่จำเป็นตอนทำเอกสารขออนุมัติและตอนตรวจสอบย้อนกลับ

### กลุ่มอ้างอิง ไม่คำนวณ — 9 ช่อง

A (No.) · B (ชื่อ) · C (บริษัท) · D (แผนก) · E (Owner) · Z (หมายเหตุ) · **AA (สถานที่ตั้งที่ใช้งาน)**

**AA ไม่เข้าคะแนน แต่ใช้แบ่ง use case ตามที่ตั้งเพื่อคิด spec Server ของแต่ละที่**
ที่ตั้งชื่อเดียวกันถือเป็นเครื่องเดียวกัน จึงต้องพิมพ์ชื่อให้ตรงกัน (จะเปลี่ยนเป็น dropdown
เมื่อได้รายชื่อที่ตั้งของแต่ละบริษัท) ถ้าบริษัทมีที่ตั้งเดียวเว้นว่างได้

**X (ความสำคัญตามความเห็นหน่วยงาน)** และ **Y (กำหนดเวลาที่ต้องการใช้งาน)** — จงใจไม่เอาเข้าสูตร เพราะ
ทุกแผนกจะเลือก "สูง - ต้องการด่วน" หมด ถ้าเอามาคิดก็ไม่ช่วยแยกอะไร
แต่มีประโยชน์ตรงที่เอาไป**เทียบกับคะแนนจริง** — ถ้าแผนกบอกด่วนมากแต่คะแนนออกมา 35
แปลว่าต้องคุยกันว่าทำไมต่างกัน

| **J** | จำนวนจุดตรวจหรือกล้องที่ทำงานพร้อมกัน | งาน Real-time สเปกขึ้นกับจำนวนสายที่ประมวลผลขนานกัน |
| **K** | ภาษาที่ต้องรองรับ | ไทยต้องใช้โมเดลใหญ่กว่า → VRAM มากกว่า |
| **L** | เวลาตอบสนองที่ยอมรับได้ | **Real-time = GPU · Batch = CPU พอ แม้เป็นงานภาพ** |
| **M** | ช่วงเวลาที่ต้องให้บริการ | 24×7 = ต้องมีเครื่องสำรอง |
| **N** | ผลกระทบเมื่อระบบตอบสนองช้าลงในช่วงใช้งานหนาแน่น | **แปลเป็น "ต้องมี GPU ของตัวเองมั้ย"** · "กระทบมาก หยุดไม่ได้" = เผื่ออุปกรณ์สำรอง |
| **O** | ระยะเวลาการจัดเก็บข้อมูล | คูณกับปริมาณข้อมูลนำเข้าต่อวัน (S) = storage ที่ต้องซื้อ |
| **P–R** | งบประมาณที่ตั้งไว้ · ข้อจำกัดอื่นๆ · ผู้ให้ข้อมูล | อ้างอิง |

#### คอลัมน์ D — ทำไมต้องถามก่อนช่องอื่น

use case แบ่งได้ 4 ประเภท และ **3 ใน 4 ประเภทไม่มีคนนั่งกดใช้** ทำให้ช่อง G/H/I
ต้องตีความต่างกัน ถ้าไม่รู้ประเภทก่อน จะกรอกผิดทั้งแถว

| ประเภท | ตัวอย่างของบริษัท | G กรอกอะไร | H | I กรอกอะไร |
|---|---|---|---|---|
| คนกดใช้เอง | Chatbot · ค้นหา SOP | คนจริง | คนพร้อมกัน | กี่คำถาม |
| **อัตโนมัติต่อเนื่อง** | **Auto Inspection สายพาน** | คนที่เข้ามาดูผล | 1–2 คน | **กี่ชิ้น กี่ภาพ** |
| **รันตามรอบเวลา** | **Big Data ปิด LOT · Predictive Maintenance** | คนที่เปิดดูรายงาน | 1–2 คน | **กี่ล็อต กี่แถวในรอบนั้น** |
| เมื่อมีเหตุการณ์ | NC Agent · สรุป RFQ | คนที่เกี่ยวข้อง | 1–2 คน | กี่เคส |

#### คอลัมน์ I — ทำไมต้องนับ "รายการ" ไม่ใช่ "ครั้ง"

เดิมถามว่า "ใช้งานกี่ครั้ง/วัน" ซึ่งวัดจาก**การสั่งงาน** แต่สิ่งที่กินเครื่องจริงคือ
**จำนวนรายการที่ AI ต้องประมวลผล** ทำให้งานที่หนักที่สุดกรอกออกมาดูเบาที่สุด

| Use case | กรอกแบบ "ครั้ง" | กรอกแบบ "รายการ" |
|---|---|---|
| Chatbot | 500 | 500 คำถาม |
| **Auto Inspection** | **0 — ไม่มีคนกด** | **5,000 ชิ้น** |
| **Big Data ปิด LOT** | **1 — รันคืนละครั้ง** | **12,000 ล็อต** |
| Predictive Maintenance | 1 | 3,000 รายการประวัติ |

ถ้าใช้หน่วย "ครั้ง" จะตั้งสเปกต่ำกว่าความจริงมากสำหรับงานที่หนักที่สุด
ช่วงตัวเลือกจึงขยายถึง **มากกว่า 100,000 รายการ** ด้วย

### โซน B — ทีม AI/IT เติมทีหลัง (S–X)

| คอลัมน์ | ถามอะไร | ทำไมแผนกตอบไม่ได้ |
|---|---|---|
| **S** | ปริมาณข้อมูลนำเข้าต่อวัน | คิดจากจำนวนรูป × ขนาดไฟล์ ซึ่ง IT คำนวณเองได้ |
| **T** | ขนาดคลังเอกสารทั้งหมด (RAG) | แผนกรู้ว่ามีเอกสารกี่ฉบับ แต่ไม่รู้ว่ากี่ GB |
| **U** | ความละเอียดของภาพ | เป็นสเปกกล้อง IT/วิศวกรรมรู้ |
| **V** | รูปแบบการติดตั้ง (Server ของที่ตั้ง / เครื่องที่หน้างาน) | เรื่องสถาปัตยกรรม |
| **W** | ความจำเป็นในการปรับโมเดลด้วยข้อมูลขององค์กร | ศัพท์เทคนิค (สำเร็จรูป / RAG / Fine-tune) |
| **X** | ความถี่ในการฝึกโมเดลใหม่ | ต้องรู้ก่อนว่าโมเดลทำงานยังไง |

**คอลัมน์ W มี 3 ระดับ ไม่ใช่ 2** — ตัวกลาง "ไม่ต้องเทรน แต่ให้อ่านเอกสารบริษัท (RAG)"
สำคัญมาก เพราะ use case งานเอกสาร/chatbot ส่วนใหญ่ตกอยู่ตรงนี้ ถ้าไม่มีตัวเลือกนี้
คนจะเลือก "ต้อง Fine-tune" ทั้งที่ไม่ต้อง → ระบบคิดว่าต้องซื้อ GPU สำหรับเทรนเพิ่มโดยไม่จำเป็น

**คอลัมน์ X มีตัวเลือก "ไม่ต้องเทรนเลย"** ซึ่งต่างจาก "ครั้งเดียวจบ"
(ครั้งเดียวจบ = ยังต้องเทรน 1 ครั้ง จึงยังต้องหา GPU มาเทรน)

| กรณี | คะแนนรวม | ระดับ | อันดับ | ช่องที่ขาด |

| ยังไม่ได้กรอก Use Case | *(ว่าง)* | *(ว่าง)* | *(ว่าง)* | *(ว่าง)* |

ช่อง "ระดับ" และ "ช่องที่ขาด" ขึ้นพื้นแดงอัตโนมัติ · คะแนนย่อยที่กรอกไปแล้วยังแสดงปกติ ·
