# ตัวช่วยกรอก 3 use case (เตรียมเมื่อ 2026-10-12)

ไฟล์นี้ช่วยให้คุณกรอกช่องที่ยังว่างของ 3 case ได้เร็ว ไม่ได้บันทึกอะไรลงระบบ

**วิธีใช้**
1. เปิด Artifact → กดแก้ไข use case → เลือกค่าในช่องที่ว่างตามที่ตอบ (เลขข้อ = ลำดับในรายการที่กดเลือก ไม่นับ "ยังไม่ได้เลือก")
2. หรือกรอกคอลัมน์ "ตอบ" ในไฟล์นี้แล้วส่งให้ผมนำเข้าให้ (ผมจะเขียนเฉพาะช่องที่คุณตอบ)
3. คอลัมน์ **"ข้อสันนิษฐาน"** คือที่ผมคาดจากข้อความในไฟล์ ไม่ใช่ข้อมูลจริง ต้องให้เจ้าของ case ยืนยัน ถ้าไม่แน่ใจให้เว้นว่างไว้ ระบบจะแสดง "ข้อมูลไม่ครบ" แทนการเดา

**ขั้นต่ำ:** ต้องกรอกครบ **10 ช่องในส่วนที่ 1** ถึงจะมีคะแนนและอันดับ ส่วน **5 ช่องในส่วนที่ 2** ใช้ตอนคิด spec server (เฟส 3)

## ตัวเลือกของแต่ละช่อง

### ส่วนที่ 1 — 10 ช่องที่ใช้คิดคะแนน

| ช่อง | ตัวเลือก (เลขข้อ) |
|---|---|
| ปริมาณเวลาที่ใช้กับงานนี้ในปัจจุบัน | **1** น้อยกว่า 4 ชั่วโมง/สัปดาห์ (ไม่ถึงครึ่งวันทำงาน) *(คะแนน 1)*<br>**2** 4 - 10 ชั่วโมง/สัปดาห์ (ประมาณ 1 วันทำงาน) *(คะแนน 2)*<br>**3** 10 - 20 ชั่วโมง/สัปดาห์ (ประมาณ 2 วันทำงาน) *(คะแนน 3)*<br>**4** 20 - 40 ชั่วโมง/สัปดาห์ (เทียบเท่าบุคลากร 1 คนเต็มเวลา) *(คะแนน 4)*<br>**5** มากกว่า 40 ชั่วโมง/สัปดาห์ (มากกว่า 1 คนเต็มเวลา) *(คะแนน 5)* |
| มูลค่าความสูญเสียต่อปี | **1** ไม่สามารถประเมินเป็นตัวเงินได้ หรือไม่มีความสูญเสียโดยตรง *(คะแนน 3)*<br>**2** น้อยกว่า 100,000 บาท/ปี *(คะแนน 2)*<br>**3** 100,000 - 500,000 บาท/ปี *(คะแนน 3)*<br>**4** 500,000 - 2,000,000 บาท/ปี *(คะแนน 4)*<br>**5** มากกว่า 2,000,000 บาท/ปี *(คะแนน 5)* |
| รูปแบบการจัดเก็บข้อมูล | **1** เอกสารกระดาษ / บันทึกด้วยลายมือ - ต้องแปลงเป็นดิจิทัลก่อน *(คะแนน 1)*<br>**2** ไฟล์ Excel / CSV - นำไปใช้ได้ทันที *(คะแนน 4)*<br>**3** ฐานข้อมูลในระบบ (ERP / MES / SQL) - ดึงข้อมูลอัตโนมัติได้ *(คะแนน 5)*<br>**4** ภาพถ่าย / ไฟล์รูปภาพ *(คะแนน 3)*<br>**5** ไฟล์เสียง / วิดีโอ *(คะแนน 2)*<br>**6** ยังไม่มีการจัดเก็บ - ต้องเริ่มเก็บใหม่ *(คะแนน 1)* |
| ข้อมูลย้อนหลังที่มี | **1** ไม่มีข้อมูลย้อนหลัง - ต้องเริ่มเก็บใหม่ *(คะแนน 1)*<br>**2** น้อยกว่า 1 ปี - อาจไม่เพียงพอต่อการฝึกโมเดล *(คะแนน 2)*<br>**3** 1 - 3 ปี - เพียงพอในระดับหนึ่ง *(คะแนน 4)*<br>**4** มากกว่า 3 ปี - เพียงพอ *(คะแนน 5)* |
| สิทธิ์นำข้อมูลมาใช้ | **1** ได้ทันที - ข้อมูลอยู่ในความดูแลของหน่วยงาน *(คะแนน 5)*<br>**2** ต้องขออนุมัติก่อน - อยู่ในความดูแลของหน่วยงานอื่นหรือ IT *(คะแนน 3)*<br>**3** ไม่สามารถขอได้ หรือยังไม่แน่ใจ - เป็นของลูกค้าหรือผู้ขาย *(คะแนน 1)* |
| เชื่อมต่อกับระบบเดิม | **1** ไม่จำเป็น - ระบบทำงานแยกอิสระได้ *(คะแนน 5)*<br>**2** จำเป็นบางส่วน - เชื่อมต่อผ่านการนำเข้า/ส่งออกไฟล์เป็นรอบ *(คะแนน 3)*<br>**3** จำเป็น - ต้องอ่านและเขียนข้อมูลกับระบบเดิมแบบทันที *(คะแนน 1)*<br>**4** ยังไม่สามารถระบุได้ - ต้องหารือกับฝ่าย IT *(คะแนน 2)* |
| ผู้ดูแลระบบหลังส่งมอบ | **1** มี - หน่วยงานมีผู้รับผิดชอบดูแลต่อ (ระบุชื่อในหมายเหตุ) *(คะแนน 5)*<br>**2** ยังไม่แน่ใจ - อยู่ระหว่างจัดหาผู้รับผิดชอบ *(คะแนน 3)*<br>**3** ไม่มี - ต้องพึ่งพาหน่วยงานภายนอกตลอด *(คะแนน 1)* |
| ผลเมื่อ AI ผิดพลาด | **1** ต่ำ - ตรวจพบและแก้ไขได้ทันที ไม่กระทบผู้อื่น *(คะแนน 1)*<br>**2** ปานกลาง - เสียเวลาดำเนินการใหม่ หรือเกิดต้นทุนเพิ่ม *(คะแนน 3)*<br>**3** สูง - ของเสียถึงมือลูกค้า เกิดอันตราย หรือผิดข้อกำหนดกฎหมาย *(คะแนน 5)* |
| ต้องตรวจซ้ำโดยคน | **1** ไม่จำเป็น - ใช้ผลลัพธ์จาก AI ได้ทันที *(คะแนน 1)*<br>**2** สุ่มตรวจบางส่วน - เฉพาะรายการที่ AI ไม่มั่นใจ *(คะแนน 2)*<br>**3** ตรวจสอบทุกรายการ - บุคลากรต้องตรวจซ้ำทั้งหมด *(คะแนน 4)* |
| ระดับความลับของข้อมูล | **1** สาธารณะ - เปิดเผยได้ ไม่มีผลกระทบ *(คะแนน 1)*<br>**2** ภายในองค์กร - ห้ามเผยแพร่ออกนอกบริษัท *(คะแนน 2)*<br>**3** ลับ - ต้องจำกัดสิทธิ์การเข้าถึง *(คะแนน 4)*<br>**4** ลับที่สุด - มีข้อมูลส่วนบุคคล อยู่ภายใต้ PDPA *(คะแนน 5)* |

### ส่วนที่ 2 — 5 ช่องที่ใช้คิด spec (ไม่มีผลต่อคะแนน)

| ช่อง | ตัวเลือก (เลขข้อ) |
|---|---|
| ลักษณะการเริ่มทำงาน | **1** ผู้ใช้เรียกใช้งานเอง - เปิดใช้เป็นครั้งคราว<br>**2** ทำงานอัตโนมัติต่อเนื่อง - ระบบทำงานเอง ไม่มีผู้เรียกใช้<br>**3** ประมวลผลตามรอบเวลา - เช่น ทุกคืน หรือทุกสัปดาห์<br>**4** ทำงานเมื่อเกิดเหตุการณ์ - เช่น มีใบ NC เข้าสู่ระบบ |
| ประเภทข้อมูลนำเข้า | **1** ข้อความ / เอกสาร<br>**2** ภาพถ่าย<br>**3** เสียง<br>**4** วิดีโอ<br>**5** ตัวเลข / ตาราง<br>**6** ผสมหลายประเภท |
| เวลาตอบสนองที่ยอมรับได้ | **1** ทันที - ไม่เกิน 2 วินาที (ตอบกลับในกระบวนการทันที)<br>**2** เร็ว - 2 ถึง 10 วินาที (ผู้ใช้รอที่หน้าจอได้)<br>**3** ภายในไม่กี่นาที<br>**4** ภายใน 1 ชั่วโมง หรือภายในรอบกะ<br>**5** ภายในรอบวัน - ประมวลผลกลางคืน เสร็จก่อนเริ่มงานเช้า |
| รูปแบบการติดตั้ง | **1** ติดตั้งที่ Server ของที่ตั้ง (ห้อง Server ของโรงงาน/สาขา) - ส่งข้อมูลผ่านเครือข่ายได้<br>**2** ต้องติดตั้งที่หน้างาน - ติดตั้งข้างเครื่องจักรหรือสายพาน<br>**3** ยังไม่สามารถระบุได้ |
| การปรับโมเดลด้วยข้อมูลองค์กร | **1** ไม่จำเป็น - ใช้โมเดลสำเร็จรูปได้ (งานความรู้ทั่วไป)<br>**2** ไม่ต้องฝึกโมเดล แต่ให้เข้าถึงเอกสารขององค์กร (RAG)<br>**3** จำเป็น - ต้อง Fine-tune ด้วยข้อมูลหรือภาพขององค์กร<br>**4** ยังไม่สามารถระบุได้ |

ช่อง "ผู้ใช้พร้อมกันสูงสุด" (ใน sheet 2) ก็ใช้คิด spec เช่นกัน เป็นช่วงจำนวนคน เลือกจากฟอร์มได้โดยตรง

## Case 2 — AI จัดคนเข้าเครื่องตาม Skill Matrix แทนหัวหน้างาน

| ช่อง | ไฟล์ต้นฉบับบอกอะไร | ข้อสันนิษฐาน (ต้องยืนยัน) | ตอบ |
|---|---|---|---|
| ชั่วโมงที่ใช้ต่อสัปดาห์ | หัวหน้างานจัดคนเอง (Manual) แต่ไม่ได้ระบุชั่วโมง | — | |
| มูลค่าความสูญเสียต่อปี | ชีต Man Alocation 1 บอกความเสี่ยง "พนักงานทักษะไม่ตรงทำให้เกิดงานเสีย (NG)" แต่ไม่มีมูลค่า | — | |

| ข้อมูลย้อนหลัง | มี "ประวัติผลงานรายบุคคล" แต่ไม่ระบุว่านานเท่าไร | — | |

| เชื่อมกับระบบเดิม | Man Alocation 1: ดึงแผนผลิตจาก ERP และข้อมูลเข้างานจากระบบลงเวลา | **2** บางส่วน (นำเข้าไฟล์) หรือ **3** อ่าน/เขียนตรง | |
| ผู้ดูแลหลังส่งมอบ | ไม่มีในไฟล์ | — | |

| ตรวจซ้ำโดยคน | Man Alocation 1: หัวหน้างาน "อนุมัติหรือปรับเปลี่ยน" ก่อนเริ่มงาน | **3** ตรวจทุกรายการ | |
| ระดับความลับ | มีข้อมูลพนักงานรายบุคคล (Payroll, ประวัติผลงาน) | **3–4** ลับ / PDPA | |
| ลักษณะการเริ่มทำงาน | Man Alocation 1: จัดก่อนเริ่มงาน (Pre-Production) ตามพนักงานที่เข้ากะนั้น | **3** ตามรอบเวลา | |
| ประเภทข้อมูลนำเข้า | Skill Matrix, ตาราง Fix คน Fix เครื่อง, แผน MPS | **5** ตัวเลข / ตาราง | |
| การปรับโมเดล | Man Alocation 1/3: ใช้ Optimization (Python, OR-Tools) ไม่ใช่โมเดลที่ต้องฝึก | **1** ไม่จำเป็น | |
| เวลาตอบสนอง / รูปแบบติดตั้ง | ไม่มีในไฟล์ | — | |

**ช่องข้อความที่ว่าง (ไฟล์ไม่มี):** ผู้รับผิดชอบ, สถานที่ตั้ง, ปริมาณข้อมูล, กำหนดเวลาที่ต้องการ, ความสำคัญตามความเห็นหน่วยงาน, จำนวนผู้ใช้ (หัวหน้างานกี่คน) และช่อง sheet 2 ที่เหลือ

> หมายเหตุ: Man Alocation 2 เสนอทางเลือกที่ใช้ AWS/Azure/OpenAI/Claude API ซึ่งขัดกับข้อตกลง on-premise ใช้ได้เฉพาะระดับ 1 (Python + OR-Tools) ซึ่งไม่ต้องใช้ GPU
